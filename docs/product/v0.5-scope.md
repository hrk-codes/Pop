# V0.5 Scope: Local-First Memory and Personalization

**Current milestone:** Phase 82 complete as a design and stability audit

**Runtime status:** BLOCKED by unfinished V0.1-V0.4 foundations

## Product goal

POP should stop asking the user to repeat stable preferences while storing as little durable data as
possible. The first useful memory flow will be explicit and user-controlled:

```text
User asks POP to remember a preference
  -> POP shows the value, scope, source, retention, and cloud policy
  -> user confirms when policy requires it
  -> local durable record
  -> future relevant task retrieves a bounded set
  -> POP shows which memories were used
```

## Included in V0.5

- Explicit preference, knowledge, and limited interaction-summary memories
- Global, application, domain, task, and explicitly identified project scopes
- Provenance, confidence, sensitivity, retention, status, and cloud policy
- Deterministic save, ask, ignore, and deny decisions
- Local SQLite storage with versioned migrations
- FTS5 only after structured CRUD, scope, conflict, and expiry behavior is correct
- Explicit remember, inspect, edit, forget, export, and clear-all controls
- Bounded retrieval, visible usage reasons, and derived personalization
- Secret denial and strict separation from action authority

## Excluded

- Continuous activity, keystroke, clipboard, browser, screenshot, email, or chat history
- Raw transcript storage by default
- Automatic repository crawling or project identity inferred from arbitrary paths
- A visual-memory or screenshot database
- Direct model writes to the memory database
- Silent permanent behavioral learning
- Vector databases or embeddings without retrieval evaluation evidence
- Memory-derived action permission, approval, risk reduction, or autonomous execution

## Completion standard

V0.5 is not complete when records can merely be stored. It is complete when the user can answer what
POP remembers, why it remembers it, where it applies, who supplied it, whether it can leave the device,
how it affected a result, and how to correct or delete it. Deletion must remove every retrieval,
profile, cache, and index influence.
