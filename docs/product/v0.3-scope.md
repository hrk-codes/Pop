# POP V0.3 Scope

## Product goal

V0.3 lets POP understand an approved region of a generic Windows application when dedicated structured
adapters and bounded UI Automation are insufficient. Vision is a fallback sensor. POP remains unable to
control the computer.

## Included after prerequisite gates pass

- Read-only, bounded foreground-window UI Automation
- Normalized UI elements with provenance, reliability, limits, and expiry
- Independent visual permissions defaulting to `NONE`, including allow once
- Manual DPI-aware region selection and one-shot in-memory capture
- Visible selection, preview, cloud activity, cancellation, and privacy status
- Local crop, aspect-preserving resize, PNG encoding, and payload limits
- Provider-neutral vision interface and configurable Groq vision adapter
- Strict structured visual observations and output validation
- Short-lived UIA/OCR/vision context with conflict-preserving sensor fusion
- Structured-first fallback routing and restrained user-invoked visual questions

## Explicitly excluded

Continuous or periodic capture, screenshot history, global OCR loops, hidden surveillance, mouse/keyboard
automation, UIA control patterns, browser automation, terminal/file actions, messaging/posting, tools,
agents, action planning, voice/microphone, long-term visual memory, and V0.4 capabilities.

## Trust and privacy behavior

Unknown apps have no visual permission. Capture requires monitoring, app policy, visual policy, current
target identity, sensitivity checks, and consent before a frame exists. Raw images are ephemeral and not
stored by default. Every cloud request is visible, minimized, rate-limited, and restricted to an approved
provider.

## Latency behavior

POP uses adapters and UIA before visual analysis. UIA is bounded and event-driven; image preprocessing is
local; capture resources live for one frame; duplicate fresh observations may be reused only within a
strict TTL. Idle visual CPU and API requests target zero.

## Failure behavior

Protected, denied, changed, stale, oversized, unsupported, or uncertain content fails closed. POP reports
limitations plainly and never invents controls or UI state.

## Current project status

Phase 26 is design-only and blocked because V0.1 and V0.2 runtimes are absent. No UIA, capture, OCR,
vision-provider, or image-retention code exists in the repository.

## Future extension

V0.3 supplies fresh, source-labelled observations that V0.4 could later use to propose separately
authorized actions. It intentionally supplies no execution authority itself.
