# V0.2 Context Model Design

**Status:** Design only; Phase 14 implementation is blocked by the V0.1 completion gate.

V0.2 adds temporary understanding between validated observations and suggestions. It does not add
long-term memory, autonomous action, screen capture, or AI-based event classification.

## Pipeline

```text
authorized structured event
  -> context-state reducer
  -> current activity
  -> local intent candidates
  -> inspectable confidence signals
  -> cooldown and interruption policy
  -> zero or one primary suggestion
  -> explicit user action
  -> context budget + sanitization
  -> provider-neutral AI request
  -> validated response session
```

The permission and sensitive-content gates remain before context aggregation. A denied event must not
become temporary context merely because it never reaches an AI provider.

## Concept boundaries

### RawEvent

A `RawEvent` is one immutable, versioned observation from an authenticated adapter or POP Core. It
describes what changed, not what the user is doing.

```ts
interface RawEvent<TPayload = unknown> {
  version: '1';
  id: string;
  source: 'core' | 'vscode' | 'chrome';
  type: string;
  timestamp: number;
  payload: TPayload;
}
```

Examples include `browser.typing.paused`, `editor.selection.changed`, and
`system.foreground.changed`. Runtime schemas must narrow `payload` by source and event type before the
event reaches the context-state engine.

### ContextState

A `ContextState` is the reducer's current, ephemeral interpretation of several accepted events. It is
replaceable working context, not an event history.

```ts
interface ContextState {
  id: string;
  application: 'vscode' | 'chrome' | 'unknown';
  surface?: string;
  activity: Activity;
  status: 'active' | 'paused' | 'stale';
  selectedContent?: ContextItem;
  referenceContent?: ContextItem;
  draftContent?: ContextItem;
  editable: boolean;
  lastMeaningfulEvent: string;
  updatedAt: number;
  expiresAt: number;
}

interface ContextItem {
  id: string;
  classification: 'PUBLIC' | 'USER_CONTENT' | 'SOURCE_CODE';
  content: string;
  capturedAt: number;
}
```

Blocked and sensitive content never becomes a `ContextItem`. Content caps are enforced before storage,
and state is held in memory unless a later, explicit privacy-reviewed requirement says otherwise.

### Activity

`Activity` answers “what is happening now?” independently of the application name.

```ts
type Activity =
  | 'IDLE'
  | 'READING'
  | 'TEXT_SELECTED'
  | 'WRITING'
  | 'REPLY_COMPOSITION'
  | 'CODE_READING'
  | 'CODE_SELECTED'
  | 'CODE_EDITING'
  | 'SEARCHING'
  | 'UNKNOWN';
```

Activity is deterministic. For example, Chrome plus an approved X reply surface plus a focused
editable element yields `REPLY_COMPOSITION`; VS Code plus a stable non-empty selection yields
`CODE_SELECTED`.

### IntentCandidate

An `IntentCandidate` is a locally generated operation that could help with the current activity. It is
not yet permission to interrupt or call AI.

```ts
interface IntentCandidate {
  intent: IntentType;
  contextStateId: string;
  reasons: string[];
  requiresAI: boolean;
}
```

One activity can produce several candidates. `CODE_SELECTED` may produce `EXPLAIN_CODE`,
`FIND_POSSIBLE_BUG`, `SIMPLIFY_CODE`, and `IMPROVE_CODE`.

### Confidence

`Confidence` is an inspectable local score, never an LLM judgment.

```ts
interface Confidence {
  score: number;
  signals: Array<{
    id: string;
    weight: number;
    explanation: string;
  }>;
}
```

The score is clamped from `0` to `1`. Configurable thresholds map it to no action, passive state,
subtle signal, or contextual action. Negative signals include active typing, unstable selection,
recent dismissal, cooldown, and exhausted interruption budget.

### SuggestionCandidate

A `SuggestionCandidate` combines one intent with an action descriptor and confidence result. Ranking
and suppression return zero or one proactive primary suggestion.

```ts
interface SuggestionCandidate {
  id: string;
  contextStateId: string;
  intent: IntentType;
  action: ContextAction;
  confidence: Confidence;
  explanation: string;
}
```

The `explanation` powers “Why did POP appear?” locally. It should reference signals such as “reply field
focused” and “typing paused,” never hidden model reasoning.

### ResponseSession

A `ResponseSession` is short-lived state for refining one validated AI result without rebuilding the
entire interaction.

```ts
interface ResponseSession {
  id: string;
  task: IntentType;
  sourceContextId: string;
  currentResponse: string;
  refinementCount: number;
  createdAt: number;
  expiresAt: number;
}
```

It expires when the source context expires, the foreground application changes, monitoring turns off,
permission is revoked, or the refinement limit is reached. It stores no executable model actions.

## Context lifecycle

The engine holds one current state plus a very small bounded stack of `CURRENT`, `REFERENCE`, and
`PREVIOUS` items. Each item has a TTL and source context ID.

Immediate invalidation occurs on monitoring off, permission revocation, source disconnect, foreground
application change, domain change, or relevant document change. Time-based expiry handles abandoned
selections, drafts, and response sessions. Expiry removes content, not only the visible activity label.

## Example transition: VS Code

```text
foreground=vscode
  + editor focused
  + stable non-empty selection
  -> ContextState(activity=CODE_SELECTED)
  -> four local intent candidates
  -> confidence and suppression select at most one subtle suggestion
  -> user opens action ring and chooses Find Bug
  -> optional permitted diagnostic + selection enter context budget
  -> AI only after explicit action
```

Switching to Chrome immediately invalidates the active VS Code selection context.

## Example transition: browser writing

```text
foreground=chrome
  + approved domain
  + non-sensitive editable field focused
  + draft changed
  + typing paused
  -> ContextState(activity=WRITING)
  -> IMPROVE_WRITING candidate
  -> local confidence score
  -> suggestion may be suppressed, subtle, or shown
```

The X-specific `REPLY_COMPOSITION` specialization is intentionally deferred to Phase 19.


Responsibilities:

| File           | Responsibility                                                            |
| -------------- | ------------------------------------------------------------------------- |
| `types.ts`     | Public event-input and ephemeral-state contracts                          |
| `state.ts`     | Safe initial state and bounded context-stack operations                   |
| `reducer.ts`   | Pure deterministic event-to-state transitions                             |
| `engine.ts`    | Validation-ready orchestration and state publication                      |
| `signals.ts`   | Normalized local facts used to infer activity                             |
| `lifecycle.ts` | Monitoring, foreground, domain, document, and permission invalidation     |
| `expiry.ts`    | Clock-injected TTL calculation and content removal                        |
| test files     | Simulated transitions, invalidation, TTL, and sensitive-content exclusion |

The package may depend on `@pop/protocol`, `@pop/context`, and `@pop/shared` once those V0.1 packages
exist. It must not depend on React, Tauri, extensions, `@pop/suggestion-engine`, or `@pop/ai`. This keeps
context interpretation deterministic and independently testable.

## Phase 14 verification contract

Implementation should not be accepted until simulated tests prove:

- typing started produces `WRITING` without any AI call;
- an approved reply-surface signal can produce `REPLY_COMPOSITION` without embedding X DOM logic;
- a stable VS Code selection produces `CODE_SELECTED`;
- application/domain/document changes remove incompatible content immediately;
- monitoring off and permission revocation clear content;
- TTL expiration clears both active state and stored context items;
- malformed or blocked events cannot enter the reducer;
- a fake clock makes every lifecycle test deterministic.

Phase 14 ends at tested context aggregation. Candidate generation, confidence ranking, and proactive UI
remain later phases.
