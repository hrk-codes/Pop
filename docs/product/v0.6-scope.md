# V0.6 Scope: Tools, MCP, and Bounded Workflows

**Current milestone:** Phase 111 complete as a design and stability audit

**Runtime status:** BLOCKED by unfinished V0.1-V0.5 foundations

## Product goal

POP should prefer an approved structured tool or API over fragile visual automation when both can
perform the same task. Tools expand capability, not authority.

## Included in V0.6

- A POP-owned `ToolDefinition`, `ToolCall`, `ToolResult`, registry, and deterministic policy
- Internal, native API, local MCP, and remote MCP adapter sources
- Server, tool, and capability-level permissions
- Explicit trust and structured process configuration for local stdio servers
- Streamable HTTP over HTTPS for approved remote servers
- Credential references backed by future OS-secure storage
- Input/output schema validation, result limits, provenance, sanitization, and verification
- One read-only external integration before any controlled write integration
- One-time approval and preview for consequential writes
- Metadata-only tool history and bounded, stop-on-failure workflows

## Excluded

- Automatic MCP server installation or connection
- Arbitrary shell strings or unrestricted process execution
- Full environment inheritance by child processes
- Credentials in memory, settings, logs, React persistence, prompts, or server JSON
- Unrestricted destructive, financial, security, admin, or messaging tools
- Tool descriptions, results, webpages, memories, or model proposals as authority
- Unlimited retries, background loops, self-extending plans, or unrestricted autonomy
- MCP Roots, Sampling, Logging, legacy HTTP+SSE, Apps, Tasks, or prompts as V0.6 requirements

## Completion standard

V0.6 is complete only when a user can inspect every connection, permission, proposed argument,
approval, result source, verification outcome, and workflow step. Unknown servers remain disconnected,
destructive capabilities remain denied, credentials remain isolated, and no tool result becomes memory
or action authority without its separate governing policy.
